# IQ Ascent — Implementation Plan

> **Status: complete.** 88 tests green, `** BUILD SUCCEEDED **`, verified running on the
> iOS 27 simulator across all 10 floors plus the report.

**Goal:** An iOS puzzle game that measures reasoning across 10 themed levels and produces
a personalised assessment report with an IQ estimate, an eight-axis ability profile, and
specific coaching advice.

**Architecture:** A pure-Foundation `Core` holds the models, all 19 puzzle generators, the
scoring maths and the coaching engine, and imports neither UIKit nor SwiftUI. It compiles
for both the iOS app (through Xcode's folder synchronisation) and a root-level SwiftPM
package (for `swift test`), so there is one source of truth and two build systems that
cannot disagree. A SwiftUI layer renders and orchestrates.

**Tech stack:** Swift 5 language mode, iOS 27, SwiftUI + Canvas, Swift Concurrency
(`@Observable`), AVFoundation, UIKit feedback generators, SwiftPM + XCTest.

Full design rationale: `docs/superpowers/specs/2026-10-02-iq-ascent-design.md`.

## Defects found and fixed during verification

Each was caught by running the thing, not by reading it.

| Defect | Cause | Fix |
| --- | --- | --- |
| Duplicate matrix options made one choice unfillable | `step` and its complement can coincide mod 360 | `GenSupport.uniqueShapes` guarantees a distinct option set |
| Tapping left-to-right solved every ordering item | the answer was the identity permutation | answer is now the real permutation of the presented order |
| Mid-floor difficulty dips | generators clamped θ below the requested value (arithmetic caps at 3.2) | `pickKind` only offers kinds whose ceiling reaches the ramp |
| `mirrorImage` ignored its requested θ, breaking ramp monotonicity | hardcoded `theta: 2.8` | honours the requested θ |
| Two generator retries reset θ to 2.0 | recursion passed a fixed θ | retries preserve the requested θ |
| Matrix cells could use `circle`/`cross`/`square` | `rowAndColumn` indexed the full shape list | indexes the rotation-sensitive palette |
| Rotation and mirror items had no distinguishable answer | 4-fold symmetric shapes were in the palette | generators draw from `rotationSensitive` / `handed` |
| Some shape options rendered as empty tiles | self-intersecting SwiftUI path filled nothing | geometry moved to `Core`, now asserted for area and bounding box |
| **Crash** on the memory floor | `AVAudioPlayerNode.scheduleBuffer` raises an uncatchable ObjC exception when the buffer format does not match the node | graph pinned to one explicit 44.1 kHz format; every precondition re-checked immediately before scheduling |
| Memory items could never be answered | `guard case .presenting, case .presentingAll` could never both be true | accepts either presenting phase |
| Saved progress silently failed to load | `JSONEncoder`'s default date strategy is a reference-date double, not ISO 8601 | explicit ISO 8601 on both encoder and decoder |
| Adaptive floors got *harder* for weak players | the shift was clamped to ≤ the base ramp | ramp is shifted by a bounded amount instead of blended |

### Deliberate DEBUG-only affordances

`xcrun simctl launch <device> moon.TestIQ -uiRoute report|game|intro -uiLevel N -uiSection S`
opens a screen directly. Wrapped in `#if DEBUG`. Headless simulator runs have no tap
injection, so this is the only way to verify a screen without playing to it — and it is a
layout problem that a unit test cannot catch.

## Not done

- No localisation, analytics, cloud sync or IAP, by design.
- `GameViewModel` itself is not unit tested: it is `@MainActor` and typed against
  SwiftUI's `MemoryGridView.Phase`. All the decisions it makes (star thresholds, item
  scoring, ramp construction) were moved into `Core` specifically so they *could* be tested.
- Progress is per-device with no backup.
